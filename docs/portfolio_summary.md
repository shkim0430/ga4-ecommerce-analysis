# 포트폴리오 요약

이 프로젝트에서 한 일, 검증한 것, 확인하지 못한 것, 주장하지 않는 것을 사실 기준으로 정리한 문서입니다. 데이터는 난독화된 공개 샘플(`bigquery-public-data.ga4_obfuscated_sample_ecommerce`, 2020-11-01 ~ 2021-01-31)이라 절대값은 실제 Google Merchandise Store와 다를 수 있습니다.

## (a) 프로젝트 한 줄 소개

GA4 + BigQuery 공개 이커머스 샘플로 구매 퍼널·채널·코호트 재구매·고객 세그먼트·상품 단위 분석 SQL과 Streamlit 대시보드, 주간 KPI 엑셀 리포트를 만들고, 그 과정에서 찾은 데이터 이상을 검증해 문서화한 개인 프로젝트입니다.

## (b) 이력서용 3줄

- GA4·BigQuery 공개 이커머스 샘플(난독화 데이터, 3개월)로 퍼널·채널·코호트 재구매·세그먼트·상품 단위 분석 SQL 15개 파일을 작성하고, 결과를 Streamlit 대시보드 6개 화면과 주간 KPI 엑셀 리포트 13개(과거 13주)로 구현
- 이벤트별 독립 집계 퍼널을 사용자 단위 교집합 퍼널로 재설계(구매 이벤트 유저 4,419명 → 전 단계 경험 유저 2,915명)하고, 장바구니 → 체크아웃 이탈 54.9%(add_to_cart 누락 구간을 빼고 11/16 이후로 재계산해도 55.2%)를 우선 개선 후보로 도출
- 쿼리 실행 전 dry-run과 독립 쿼리 대조(상품 매출 합 362,110, 주간 매출 합 360,837 + 제외분 = 전체 362,165)로 검증하고, 이벤트 간 item_id·item_name·item_category 불일치, add_to_cart 추적 누락, 1월 말 매출 NULL을 찾아 한계로 문서화

## (c) 구현하고 검증한 것

**구현**

- 분석 SQL 15개 파일(`sql/00`부터 `08b`까지): CTE, `_TABLE_SUFFIX` 파티션 필터, `SELECT *` 금지, 각 쿼리 상단 질문 주석. 탐색·점검용(00, 05, 05b, 05c, 06b, 06c, 06d, 08b)과 분석용(01-04, 06, 07, 08)으로 구성
- 데이터 파이프라인: `bq_client.py`(gcloud ADC 인증, 키 파일 미사용) → `fetch_data.py`(CSV 저장) → `visualize.py`(그림 6개), `dashboard.py`(6개 화면), `weekly_report.py`(주차별 엑셀)
- 분석: 구매 퍼널(교집합), 채널별 전환율과 ARPU/ARPPU, 월간·주간 코호트 재구매율, 매출 집중도 Pareto, 빈도×금액 세그먼트, 상품·카테고리 퍼널, 상품 매출 Pareto와 수량 순위, 주간 KPI
- 주간 리포트: 시트 3개(요약, 상품 매출 상위 5, 정의·한계), 전주 대비 -10% 이하 강조, 이상 구간 회색 표시, 첫 주는 전주 대비 "-"

**검증**

| 항목 | 확인한 내용 |
|---|---|
| 상품 매출 합계 | `SUM(item_revenue)` 362,110이 이벤트 매출 362,165와 0.9998 비율로 일치, 쿼리 안에 총합 검증 컬럼 포함 |
| UNNEST 중복 집계 | UNNEST 후 `purchase_revenue`를 합산하면 4.53배로 부풀려지는 것을 확인하고 `item_revenue`로만 집계하도록 규칙화 |
| 주간 매출 | 13주 합 360,837이 독립 쿼리와 일치, 완전 주 361,392 + 부분 주 773 = 362,165 |
| 주별 유저 수 | 13주 구매 유저 단순 합 4,686이 완전 주 distinct 4,406보다 커서 합산 금지로 문서화 |
| 퍼널 | 전체 기간과 2020-11-16 이후 재계산을 나란히 비교, 체크아웃 → 구매 완료율 51.5%는 동일 |
| 대시보드·리포트 | AppTest로 6개 화면 예외 없음 확인, 리포트 3개(11-02, 12-07, 01-25)의 값과 강조를 독립 기대값과 대조 |

**검증 과정에서 찾아 고친 문제**

- 구매 이벤트의 `item_category`(평평한 분류)와 조회/장바구니(경로형 분류) 형식이 달라 카테고리 퍼널의 구매 유저가 0으로 나오던 문제를 `item_name` 경유 매핑으로 해결
- 구매 전환이 0으로 나온 상품 10개 중 3개가 `item_name` 표기 차이(예: `Longsleeve` ↔ `Long Sleeve Tee`) 때문임을 확인하고 수동 매핑(매출의 2.7%) 적용
- 초기 퍼널이 단계별 유저를 독립 집계해 후속 단계를 과대 집계하던 문제를 교집합 방식으로 교체

**주요 결과 (난독화 샘플 기준, 상대 비교용)**

- 장바구니 → 체크아웃 이탈 54.9%, 체크아웃 → 구매 완료 51.5%
- 1회 구매 Mid($50~$200) 세그먼트가 전체 매출의 42.1%
- 상위 20% 유저가 매출의 56.7%, 상위 20% 상품이 매출의 69.5%

## (d) 확인하지 못한 것

- **구매 유저 4,419 vs 2,915의 차이**: 차이 1,504명 중 add_to_cart 누락 구간(11/2~11/15)으로 설명되는 것은 21명뿐이고, **나머지 약 1,483명의 원인은 확인하지 못했습니다.**
- **매출 NULL 유저 353명**: NULL 구매 이벤트 400건 중 52.3%가 2021-01-26 이후에 몰려 있지만, **나머지 약 절반(약 48%)의 원인은 확인하지 못했습니다.** 금액대 세그먼트의 Low에는 매출을 알 수 없는 유저가 섞여 있을 수 있습니다.
- **상품 매핑 미적용분**: 이름으로 연결되지 않던 purchase 매출은 **최대 4.17%**(15,082)였고, 이 중 3건(2.7%)만 수동 매핑했습니다. 미적용 "중간" 2건(4,118)을 포함해 약 1.5%(5,271)는 연결되지 않은 채이며, 조회/장바구니 쪽에만 있는 이름의 영향은 매출로 환산하지 않았습니다.
- 그 밖에 확인하지 못한 것: add_to_cart 누락과 1월 말 NULL이 생긴 원인(추적 설정 등), view_item 이벤트의 37.3%에서 items가 비는 원인, 구매 쪽 숫자 item_id가 옵션(variant) 단위라는 해석(패턴에 근거한 추정)

## (e) 하지 않은 주장

- **운영 프로세스 개선 경험이 아닙니다.** 조직의 리포트 체계나 업무 프로세스를 개선한 경험이 아니라, 공개 샘플 데이터로 만든 개인 분석 프로젝트입니다.
- **실시간 모니터링이 아닙니다.** 주간 리포트는 과거 데이터(2020-11~2021-01)를 대상으로 `--week`/`--all`로 수동 반복 생성하며, 스케줄 실행이나 알림은 없습니다.
- 실제 서비스의 성과 개선 결과가 아닙니다. 장바구니 이탈 방지 같은 개선 방향은 데이터에서 도출한 가설이며 A/B 테스트 등으로 검증하지 않았습니다.
- 인과관계를 주장하지 않습니다. 모든 결과는 기술 통계와 상대 비교입니다.
- 난독화된 샘플의 절대값을 실제 Google Merchandise Store의 성과로 주장하지 않습니다.
- 회사 내부 데이터를 다룬 업무 경험이 아닙니다.
